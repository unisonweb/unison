This transcript tests a type checking issue with recursive lets
that only have some bindings annotated. In such a scenario,
checking the whole group at once may cause problems with polymorphic
annotations, because unification variables will fail to be general
enough for the polymorphic types.

A better strategy allows sufficiently annotated types to be checked
separately after generalizing the un-annotated types. Unfortunately,
omitting ability annotations throws a wrench into this. The checker
tries to avoid this problem as much as possible, though, so the below
example should work even though there is a missing ability annotation.

``` unison
f x = g x x

g : a -> b ->{IO} a
g x y = f x
```
