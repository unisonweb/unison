Elements

data Element v loc Source #

Elements of an ordered algorithmic context. Every element but Refined declares its variable; a context is valid when no variable is declared twice and every type in it mentions only variables declared before it.

Constructors

Var (TypeVar v loc)

A variable declaration

Solved (Blank loc) v (Monotype v loc)

v is solved to some monotype

Ann v loc (Type v loc)

v has type a, maybe quantified loc contains the span of the name of the annotated v

Refined v (Type v loc)

The (already-declared) universal variable v is locally known to equal the given type. This is how GADT pattern matching refines a rigid type index inside a branch: matching e.g. NatLit : Expr Nat against a scrutinee of type Expr a records a ~ Nat for the duration of that branch. Like other branch-local context, these are introduced after a Marker and dropped on retraction.

Inconsistent v

Marks the context as inconsistent (the DK indexed-types paper's ⊥): the branch-local equalities are contradictory, so the current pattern-match branch is unreachable and its body is vacuously well-typed. Carries a (fresh) variable only so it scopes like any other element and is dropped on retraction. See inconsistent.

Marker v

used for scoping

Contexts

data Context v loc Source #

The ordered context of the typechecking algorithm.

The context is a sequence of Elements. The typechecking algorithm appends to it, retracts a suffix of it (everything after a marker), replaces one element with a few (e.g. an existential solved to an arrow, with the arrow's fresh existentials inserted before it), and asks scoping questions: is this variable declared, as an existential or a universal, and at what position? Is it solved, and to what?

The sequence only orders the elements. What is known about each variable is kept in indexes keyed by variable name, beside the sequence, and each of those maps a variable to a position in the sequence (CtxPosition): every element in the sequence has one, and vars maps each variable to its element together with that position.

So for instance, a solution proposed for an existential β may only mention variables declared before β in the context, existentials and universals alike (the universals are the rigid type variables of enclosing quantifiers). solve therefore looks up each free variable of the solution in vars, checks that it is declared as the kind of variable it occurs as, and compares its position with β's. Once β is solved, its solution is read from the same entry. anns and refinements are the same idea for term variable annotations and for the branch-local refinements of a universal.

The sequence is a finger tree whose measure includes the greatest position in a subtree (so that the element at a position can be found in logarithmic time), and a count of Inconsistent elements (so that inconsistent can tell in constant time whether the pattern-match branch being checked has been marked unreachable by contradictory GADT refinements, in which case its body is skipped).

Every change keeps the indexes describing exactly the elements in the sequence: an append or replacement records the new elements, and a retraction walks the elements it discards and forgets them. Each element is appended once and discarded at most once, so a retraction costs no more than the appends it undoes.

Segments of a context that have been retracted are plain lists (CtxSegment); the typechecker reads them whole (to generalize over their unsolved existentials, apply their solutions, or push some of them back).

data BadContext Source #

Why an element cannot go where it was put.

Constructors

DuplicateVariable

Its variable is already declared by an element of the context.

UndeclaredExistential

Its type mentions an existential not declared before it.

UndeclaredUniversal

Its type mentions a universal not declared before it.

NotRedeclared

A replacement for a variable's element does not bind the variable again, which would make every later element that mentions it ill-formed.
