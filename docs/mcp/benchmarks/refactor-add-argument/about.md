Both pass all judges.
`validation/rewrite-step.md` is the first step of `validation/good.md`: it shows the rewrite command (the rule, `rewrite.find :addLimit` and `rewrite :addLimit`) on its own because a transcript cannot read the file `rewrite` writes. It is not a solution by itself and changes nothing in the codebase; `good.md` goes on from what it printed.
Judge `method` (GREAT / PASS / FAIL) separates the structural rewrite from doing it by hand: it first checks the end state (FAIL if wrong), then greps the worker's submitted transcripts for the commands `rewrite`, `rewrite.find`, `sfind` or an `@rewrite` block (GREAT if found, PASS if not). The codebase cannot show the method, so the judge prompt carries a placeholder, `{{WORKER_TRANSCRIPTS}}`, that the harness fills with the directory of the worker's transcripts (see the protocol in `../README.md`). Validation: `validation/worker-rewrite/` (the sample of a run that used the rewrite; GREAT) and `validation/worker-by-hand/` (a by-hand run; PASS) are hand-made from `rewrite-step.md`, `good.md` and `good-manual.md`, as a worker would have submitted them, since no real worker has run; I ran the judge's grep over both (hits only in the first) and the judge's end-state commands on the `good.md` result.
The rewrite flow needs no pasting of definitions: the rule is looked up in the latest typechecked file (or the branch) and the target is the branch, so the worker's route is `unison` block with the rule, `rewrite :rule`, then `load` of the produced file (a plain `load` works in the same transcript), edit, `update`.
Validation files that read a file (`good-manual.u`, `bad-dropped-dependents.u`) stand in for the conflict file the worker edits; run them with the `validation` directory as the working directory. A `unison` block after the failed `update` is silently ignored by the runner, hence `load`.
Judges: `outcome`, `behavior`, `no-collateral` (all settled by commands), and `method` (hashes of `Report.bulletCount`, `Report.footer`, `Report.tests.footer`). Bad variants: `bad-temp-branch` (outcome), `bad-dropped-dependents` (outcome), `bad-small-limit` (behavior, outcome), `bad-collateral` (no-collateral).
