Tests the whole branch loop with no conflict: make a branch `shout`, do the work there, bring it back to `main`, end on `main`, delete the branch. The prompt states the end state and not the commands. Offline; `setup.md` adds `Text.whisper` and a test to `main` so `main` has history and a test of its own.

A good run: `branch shout`, `add` on `scratch/shout>`, `test`, `merge /shout` from `main` (a fast-forward), `delete.branch scratch/shout`. Note that deleting a branch needs the `transcript-all` tool, so the worker must reach for it (the `ucm/branches` topic says so). Traps: editing `main` directly, staying on `shout`, not deleting it, `merge shout` without the slash, merging in the wrong direction, giving up when `transcript` refuses `delete.branch`.

Judges: `outcome` (end state, current branch seen through a bare `> reflog` stanza, only `main` left, `todo`, tests, `whisper` untouched), `behavior` (inputs beyond the example, including the empty text), `used-branch` (the reflog of `main` must show `merge scratch/shout`, which is the only trace once the branch is deleted: `project.reflog` forgets deleted branches, I checked). Validated: `good.md` passes all; `bad-edit-main` fails used-branch; `bad-left-on-branch` and `bad-never-merged` fail outcome; `bad-wrong-case` (empty text) fails behavior. Open question: `used-branch` fails a worker that gets the work onto `main` some other way (for example `fork` or `update` after copying code); I think that is right for a task about the branch loop, but say if you want it softer.
