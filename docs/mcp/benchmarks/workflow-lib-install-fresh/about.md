Tests picking and installing a library from a need only: the prompt asks for `parseNats : Text -> Either Failure [Nat]` over JSON text and says to use an existing published library, not a parser of its own. The project starts with only `@unison/base`; no `setup.md` is needed. The worker must search Share, choose a JSON library (`@unison/json` is the standard one), install it into `lib` and use it.
Good run: `share-project-search` or the `share` topic, `lib.install @unison/json/releases/latest`, `parseNats` with `Decoder.run (Decoder.array Decoder.nat)`, documentation and tests. Traps: a hand-written parser (`validation/bad-handwritten.md`), installing the library but not using it, a different JSON library.
Judges: `library` (GREAT for `@unison/json`; PASS for another published JSON library that works or for a stray extra library; FAIL for a hand-written parser or an unused library), `behavior` (values on inputs the prompt did not show) and `tests-and-docs`. I rate other libraries PASS instead of FAIL because the prompt doesn't name one; Paul's idea said the judge checks for `@unison/json`, so the GREAT rating is that check.
Needs the network at the worker's run (searching and installing). `good.md` and `bad-handwritten.md` were run for real and show GREAT-type and FAIL-type state through the `library` commands; I did not run a variant that installs `@stew/json` or another alternative, so the PASS branch is untested.
Open question: the sentence "Use an existing published library ... not a parser of your own" is a hint that makes the task about install, not about whether the worker thinks of it. Without it a worker may write a parser and still satisfy the signature. Keep or drop?
Topics: `ucm/libraries`, `ucm/share`.
