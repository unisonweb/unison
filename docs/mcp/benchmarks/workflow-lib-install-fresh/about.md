Tests picking and installing a library from a need only: the prompt asks for `Order.fromJson : Text ->{Exception} Order`, reading a JSON order (customer, a list of line items with sku, quantity and price in cents, an optional note) into types that `setup.md` defines. The document is rich enough that a hand-written parser is clearly the wrong tool, so the prompt says nothing about libraries. The worker must search Share, choose a JSON library (`@unison/json` is the one `@unison` publishes), install it into `lib` and use it.
Good run: `share-project-search` or the `share` topic, `lib.install @unison/json/releases/latest`, a `Decoder.run` with `Decoder.object.at!`, `Decoder.array` and `Decoder.object.optionalAt!`, and tests. Traps: a hand-written parser (`validation/bad-handwritten.md`), installing the library but not using it, a different JSON library, defaulting a missing field, a failure that comes back as a value instead of being raised.
Judges: `library` (GREAT for `@unison/json`; PASS for another published JSON library that works or for a stray extra library; FAIL for a hand-written parser or an unused library), `behavior` (exact records on documents the prompt did not show; invalid JSON, wrong shape, missing field and wrong field type all raise, checked with `catch`) and `tests-and-docs` (tests that cover the cases are required; documentation makes it GREAT, none is PASS, since the prompt asks for neither).
Needs the network at the worker's run (searching and installing); `setup.md` and the judges are offline.
Validated for real (unison with `@unison/json` 1.4.2): `good.md` passes `behavior` (4 valid documents give the exact record, all 15 bad inputs raise) and the `tests-and-docs` and `library` commands show GREAT-type state (`lib` has base and json once, `dependencies` lists `Decoder.run`, `Decoder.array`, `Decoder.object.at!`, `Decoder.object.optionalAt!`). `bad-handwritten.md` (a scanner on `Text.indexOf` and `Text.split`, one happy-path test) installs nothing, so `library` FAILs, and `behavior` FAILs too (a missing field, a number as customer and a quantity of `"2"` give a `Right`). Not run: a variant on `@stew/json` or another library, so the PASS branch is untested. No real worker has run this task.
