What the rows say:

- The rows the convention is for gain: a small constructor returned from a
  call and matched by the caller no longer allocates. `Ok or Err from a step
  function` 2.5x, `Apply a function argument` 4.5x, `Cons list: head` 1.8x,
  `Binary tree: 1000 lookups` 1.3x (an `Optional` per lookup).
- Rows that return no constructor pay for the wider return: `Calls across
  definitions: Collatz` 0.45x and `callee first reached once the caller is
  hot` 0.55x are the worst, `fib 20` 0.71x, `Cons list: map` 0.74x,
  `murmurHashUntyped` 0.73x, `filterMap` 0.81x, the state tuple 0.85x. Every
  non-tail call now returns three (word, pointer) pairs where it returned
  one, and stores three slots on return. The Collatz row is calls through
  cells between modules, so the cost is in the uniform return through the
  stack and the caller's reload, not in register pressure; to be measured
  on its IR next, before the convention is tuned (step 7 of
  delayed-data-construction.local.md).
- The bulk of the suite (texts, bytes, floats, arrays, records, requests)
  is within 5% either way; the handler rows are slightly faster.
- Small rows (under 0.1 ms) are near the timer's resolution and their
  ratios are rough.


## Second round, the same day

After four changes, measured the same way, best of two runs each on an idle
machine (commit after 12a3f333e):

- A call's result slot is marked "never a witness" when the callee's code
  cannot yield one (`mayYieldWitness`), and a `Box` of it compiles to nothing
  and a match on it gets no witness arm. The Collatz loop had a `Box` test on
  every iteration for a Nat.
- The witness closures are loaded once at entry instead of at every site, so
  they hoist out of loops.
- LLVM's inline threshold is 600 by default where it was 225: generated
  functions carry more instructions than their work, and under the convention
  a seven-word return on top, so the step function of the Collatz loop was no
  longer inlined; with the threshold raised both modes gain on the rows that
  call across definitions (`UNISON_JIT_INLINE_THRESHOLD` was the experiment:
  Collatz 0.115 ms to 0.077 with it, off mode's hot-caller row 0.163 to 0.118).
- The C stack reserve is 128 KB where it was 256: a thousand frames of
  `Cons.map` are 272 bytes each under the convention (160 without), which
  crossed the 256 KB of native recursion a GHC worker thread's 512 KB stack
  left, and every crossing unwound the recursion through the trampoline
  (0.15x on that row).

What remains and why:

- `fib` 0.79x: two non-tail calls per invocation that cannot inline (the
  recursion), each returning seven words and storing three slots where it
  returned one and stored one.
- `Cons.map` 0.69x, `filterMap` 0.79x: the `f h` call is unknown, so its
  result keeps the `Box` test (three compares against entry-loaded pointers)
  before it goes into the constructor.
- `murmurHash of Some (i, "x")` 0.78x, tree inserts 0.82x, the state tuple
  0.72x: a value built wide and boxed at once, where a `Pack` was one
  allocation; the slot traffic of `PackWide` plus `Box` is the cost Paul
  accepted for escapes, measurable on rows that are nothing else.
- Collatz 0.85x, hot caller 0.81x: the uniform return through the stack on
  calls between modules, three slots stored and reloaded.


## Third round: narrow workers

A worker whose code cannot yield a witness (`mayYieldWitness`, the same test
that marks a call's result plain) returns one result pair, `{status, u, b}`,
instead of the convention's three (`Worker`, `feNarrow`): calls between
workers of the same module use the callee's width and pad a narrow result to
the three slots the frame has, the wrapper does the same for the uniform
entry, and a worker tail-calls another in registers only when their widths
agree, taking the stack path otherwise. Best of two runs, idle machine:
