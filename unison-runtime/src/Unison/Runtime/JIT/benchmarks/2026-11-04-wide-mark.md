# 2026-11-04: a small constructor only passed on is not built wide

`unison-src/transcripts-manual/jit-benchmarks.md` and `jit-suite.md` on two
optimized builds (`.stack-work-opt`): a94faa46a (before, the product-return
fix) and the change to `Unison.Runtime.MCode.Wide` that marks a let binding
a small constructor wide only when the body matches on the variable or
returns it somewhere (`usedWide`); one only ever passed on, as an argument
of a call, a constructor or a record, is packed as a heap value at once.
Under `UNISON_JIT=on`, best of two runs each, and under `UNISON_JIT=off`
(the interpreter), one run each; `jit-suite.md` under `on`, one run each;
macOS arm64, the machine otherwise idle. Times are the transcripts' own,
in milliseconds; the ratio is before over after, so above 1 is a gain.

Why: the library suite's `Thirty match` was 0.37x against trunk. Its loop
is `go n = cases T8 -> go (n - 1) T7; _ -> go (n - 1) T8`, and the MCode
dump showed `PackWide T7; Box 0; Call` where trunk has `Pack T7; Call`:
the pass marked every small-constructor let wide, so the `T7` was built
in the slots and boxed at once for the call, a wide pack plus a box (a
helper call that looks the type's reference up in the pool's type table
and allocates) in place of one pack. The row alone on the optimized build
was 258 µs under the defaults and 83 µs with `-wide`, against trunk's
96 µs. In the library code the suite loads, 81 sites lose their wide
pack and box this way. (A first set of per-switch timings of this row
was wrong: the shell was zsh, which does not split an unquoted variable
into words, so `UNISON_JIT` got the value "on all" and every run was
interpreted. Timings of several switches go in a bash script.)

## What it showed

- **`Thirty match` 2.9x** (0.258 to 0.088 ms), now 1.09x against trunk's
  0.096 ms: the loop's code is the code it has with the convention off.
- **The library rows that build constructors for calls gain**:
  `Set.fromList` 1.22x (0.123 to 0.100 ms, trunk's 0.099), `Map.fromList`
  1.11x, `murmurHashUntyped of Some (i, "x")` 1.18x in the JIT's suite
  (the `Some` built for the hash call). Everything else within noise in
  both suites and in the interpreter; the rows the convention is for
  (`Ok or Err`, `Cons.head`, the tree lookups) are unchanged, since a
  constructor that is returned or matched is still built wide.
- **Against trunk, what is left in the library suite**: `NatMap.fromList`
  0.87x and `Mutate a local Remote.Ref 10k times` 0.75x, each from one run
  of a row that moves 10% between rounds (the `Remote.Ref` row was 27.1 ms
  in the previous run and 29.3 ms in this one, on the same code).
