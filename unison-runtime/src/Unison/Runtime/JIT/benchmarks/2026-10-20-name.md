# 2026-10-20: `Name` without the four-argument limit

The `Name` instruction (a function value with arguments added: a lambda closing over
variables, or a known function given too few arguments) went through a C helper that took
at most four (word, pointer) pairs as C arguments; a site with more was a call-out. The
broad suite's "Mutate a local Remote.Ref 10k times" showed it: the cloud library's local
`Remote` runtime closes over eight values three times per `Ref.modify`, 30,002 exits in
10,000 iterations, and the row ran slower compiled than interpreted (33 ms against 22.6).

Now a `Name` of a known combinator is built in place (`genNameInline` in Codegen.hs): the
pool's constant for the combinator is the template, copied into one chunk with two fresh
segment arrays, as a wide constructor is built. A `Name` of a function value on the stack
still uses the helper, which takes its arguments on the Unison stack (the scratch slots
above the frame's depth, as a call's arguments go) with a base index and a count. Neither
limits the number of arguments. jit-tests.md gained a section covering every arity from 2
to 6 with every number of arguments supplied, to the known function, to it as a value, and
one at a time; the functions return their arguments as digits so that a wrong order shows.

## The Remote.Ref row

`run suite.localCloud` on its own, optimized build. Each line is one run.

| mode | before (2026-10-20, earlier) | after |
| --- | --- | --- |
| off | 22.6 ms | 21.3, 23.9 ms |
| on | 22.4 to 32 ms | 25.8, 26.8 ms |
| eager | 33.3 ms | 7.2, 13.9, 10.1, 6.7 ms, and one run of 154 ms |

With everything compiled the row is two to three times faster than interpreted, where it
was a third slower; its exits went from 30,399 to 397, none of them at a `Name`. The 154 ms
run is an outlier (the timed region is 10,000 iterations, 7 ms, so a collection landing in
it shows); the other four agree. In `on` mode the row is unchanged in kind: the loop is
over in 20 ms, before the compile thread has installed the code, so what runs is the
interpreter with the compile thread beside it, and the 2026-10-16 figure of 0.90× against
trunk was never a measurement of native code.
