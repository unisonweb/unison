Unison.Runtime.Wide

Description

The wide calling convention: whether it is on, and how many field slots a wide variable has. The design: JIT/design.md, "The wide calling convention".

A wide variable occupies wideK + 1 stack slots: its value slot on top (the lowest index in the emitter's context) and wideK field slots below it. Every yield delivers wideK + 1 slots, and every variable bound by an indirect let is wide, since its value arrives by a yield. Whether a variable is wide is a function of the code alone, so processes in either mode agree on the layout of a serialized continuation.

The convention is a property of the process, decided once, like the replacements mode in JIT/Config.hs. The interpreter alone does not gain from it (JITbenchmarks2026-10-27-wide-interpreter.md), so it is on exactly when the JIT is (UNISON_JIT=on or eager) unless UNISON_OPTIMIZATIONS=wide or -wide (Unison.Runtime.Optimizations) overrides that, for testing either combination. A compiled program's MCode has the convention of the mode it was compiled under baked in (its frames and the instructions that write them), so its file carries the mode and setWide applies it before anything loads.

Documentation

wideOn :: Bool Source #

Whether the process uses the wide calling convention.

setWide :: Bool -> IO () Source #

Chooses the convention, for a compiled program from the mode stored in its file. It has to happen before any code has used the setting: code already loaded under the other convention can't be redone, so a late choice that differs is an error.

wideK :: Int Source #

The number of field slots of a wide variable.

wideWidth :: Int Source #

The number of slots a wide variable occupies: 1 when the convention is off, so that the layout is unchanged.

widePad :: Int Source #

The slots below a wide variable's value slot: wideWidth - 1.
