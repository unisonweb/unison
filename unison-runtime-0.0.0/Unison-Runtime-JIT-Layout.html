Unison.Runtime.JIT.Layout

Description

Closure layouts, found by probing sample closures at startup (see design.md, Layouts). Generated code uses these as constants. If a layout isn't what the code generator expects, the JIT is turned off.

probeLayouts :: IO (Either String Layouts) Source #

Probes the layouts the code generator relies on. Returns an explanation if anything is unexpected.

probeLists :: Layouts -> Int -> IO (Either String ()) Source #

Lists: teaches the C helpers (jit_rt.c) the constructors of Unison.Util.Deque from samples, checks the structure of a range of lists against what the helpers assume, and then runs every helper against the Haskell operation it stands in for; each list a helper builds is checked for its structure too. Returns an explanation if anything differs.

steps (stress mode lists=N) adds a longer test: that many random operations, each done by a helper on the results of earlier ones and compared with the Haskell operation.

probeTexts :: Layouts -> Int -> IO (Either String ()) Source #

Text: the same for the text helpers. Each helper is run against the Haskell operation on texts of many shapes (one chunk, deep ropes, several bytes per character), and every text a helper builds is checked for its structure too.

steps (stress mode texts=N) adds the longer test, as for lists: that many random operations, each done by a helper on the results of earlier ones and compared with the Haskell operation.

probeBytes :: Layouts -> Int -> IO (Either String ()) Source #

The bytes helpers: the same arrangement as probeTexts for Bytes, which is the same rope with chunks of bytes, plus Bytes.at and Bytes.flatten. Stress mode bytes=N.

probeNames :: Layouts -> IO (Either String ()) Source #

Partial applications: the helper for the Name instruction against what the interpreter builds, for closures with and without arguments already captured.

probeArrays :: Layouts -> IO (Either String ()) Source #

Teaches the C array and ref helpers the wrappers' info pointers and tags, and the runtime's empty value (what Scope.array fills with).

probeMurmur :: Layouts -> IO (Either String ()) Source #

Teaches the hash helper the closures it needs to recognize and checks it against the Haskell hash (reflection then hash64ValueUntyped) on sample values of every kind it handles.

probeCompare :: Layouts -> IO (Either String ()) Source #

Universal equality and ordering: hands the comparison helpers what they need beyond the other tables (see unison_jit_cmp_init), then runs pairs of every kind of value through the C copies and the interpreter's Eq Val and Ord Val; any difference, or a pair the helper should handle and doesn't, turns the JIT off.

probeEnv :: IO (Either String ()) Source #

The handler environment: teaches the request helpers the layouts of HEnv, the IntMap under EnumMap, the STRef box inside an AffineRef and the Affine closure, from samples, and checks the native lookup against what the interpreter's resolve would find (see unison_jit_env_init in jit_rt.c).

probeRecords :: Layouts -> IO (Either String ()) Source #

Records: hands the record helpers sample records (see unison_jit_record_init), which checks the layout and the field lookup against them, then runs records through the hash and the comparison helpers against the Haskell answers.
