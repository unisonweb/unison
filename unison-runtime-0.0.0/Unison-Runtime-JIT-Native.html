Description

The interpreter's side of the boundary with native code: the C functions in cbits/jit_rt.c that the Haskell runtime calls, and nothing else. See unison-runtimesrcUnisonRuntimeJIT/design.md, "How the interpreter interacts with native code". With the JIT off nothing here is reached, because no cell ever holds code.

Three jobs, in three sections below:

  1. Entering native code. enterNative is the one call the trampoline (Machine.runNative) makes per entry; it hands over the stacks and the pool and gets a status back. Everything else native code returns is read afterwards out of the stacks' out-areas with outAp and the rest, as FrameRecords for the frames of native callers.
  2. Startup. configureNative passes the stress settings down, ctxLayout and rtsFacts fetch the numbers the code generator bakes into every function (the offsets of the C Ctx struct, the RTS's info pointers and layout constants).
  3. Addresses. The names generated code and the IR helpers call, with their addresses, which the JIT defines as absolute symbols before any module is added (helperAddresses, tableAddresses), and the C copies of the two helpers whose IR definition must shadow them.

The startup checks that run each C helper family against the interpreter are in Unison.Runtime.JIT.Native.Probes.

enterNative :: FunPtr NativeFn -> MutableByteArray (PrimState IO) -> MutableArray (PrimState IO) Closure -> MutableArray (PrimState IO) Closure -> Int -> Int -> Int -> Int -> IO Status Source #

Runs native code with the given stacks (and their size in slots) and pointers, and returns its status. Where it stopped and the frame records it wrote are read with outAp and the rest. The handler environment (an HEnv, coerced) goes in and comes back in the boxed stack's out-area (see nativeOutPtrs), so that the collector keeps the pointer right while Haskell code runs around the call.

data FrameRecord Source #

What a native caller writes down when its callee exits: which Let body to continue with (an index into the frame table), and the two sizes a Push frame needs. A negative index, -1 - i, is a Local frame instead: the environment to switch back to is in the boxed out-area at i past the first pointer, and the pending-argument count is as for a Push.
