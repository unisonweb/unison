Unison.Runtime.JIT.Native.Probes

Description

The startup checks' way into the C helpers (cbits/jit_rt.c). At startup Unison.Runtime.JIT.Layout runs every helper family (lists, texts, bytes, arrays and refs, the hash, the comparison, the handler environment, records, partial applications) against the interpreter before the JIT is allowed on, and these are the calls it makes.

The protocol is the same for each family. Haskell builds sample values and puts them in a boxed array (MutableArray of Any, so the C side gets real heap pointers), then:

  • an init call teaches the family its layouts from the samples (info pointers and tags, passed as a list of ints alongside the array) and returns 1 or the number of the check that failed;
  • a check call asks whether a sample has the structure the helpers assume;
  • a test call runs one helper on the samples (the operation and its arguments as ints) and leaves the result in the array, where Haskell compares it with what the interpreter computes.

probeClosure is the first of all: it reads a closure's raw layout, from which probeLayouts learns where each constructor keeps its fields.

probeClosure :: MutableArray (PrimState IO) (Any :: Type) -> IO [Int] Source #

Inspects a closure. Element 0 of the array is the sample, the rest are the objects in its pointer fields. Returns the raw probe output: info pointer, pointer tag, closure type, pointer count, non-pointer count, constructor tag, the payload words, then a match index per pointer field.

listInit :: MutableArray (PrimState IO) (Any :: Type) -> [Int] -> IO Int Source #

Teaches the C list helpers the constructors of a list from samples (see unison_jit_list_init), given the info pointers of Foreign, Val, Data1 and Data2. 1 if all is well, else the number of the check that failed.
