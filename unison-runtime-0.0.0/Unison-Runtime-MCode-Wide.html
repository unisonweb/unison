Unison.Runtime.MCode.Wide

Description

The wide calling convention's escape analysis, as a pass over the ANF (Unison.Runtime.Wide; design.md "The wide calling convention").

A variable bound by a let whose value arrives by a yield (a call, a match, a handle: everything letYields says) is wide: it occupies wideWidth slots, and when the yield delivered a small constructor (at most wideK fields) its value slot holds a witness and the slots below it the fields, with nothing allocated. So is a let of one variable binding a small constructor application, which the emitter packs into the slots (wideCon), when the body matches on the variable or returns it somewhere (usedWide): those are the uses the slots serve, and a constructor only ever passed on is packed as a heap value at once, since packing it wide and boxing it before the call would be the same allocation plus the box. Such a variable can be matched on and returned as it is. Where it escapes (an argument of a call, a constructor, a record, a primitive or a request; a captured variable of a closure; the value of an affine update) it has to be an ordinary heap value, which a box makes it, in place: after that the variable holds a boxed value for the rest of the path.

wideBody marks each such binder WD and places a TBox before the first escape of the variable on each path: once per path however many times the variable escapes after, and not at all on a path where it never does, so a value that is only matched on costs no allocation. The result says everything the emitter (Unison.Runtime.MCode) needs: it lays a WD binder out wide, emits a Box for each TBox, checks the two invariants (WD only on a let of one variable that yields or builds a small constructor; a TBox only of a wide variable in scope) and decides nothing itself. The pass runs last over every body the emitter sees, the unoptimized copy of a rewritten lambda included, so a box is at the same frame in both.

With the convention off the yielding binders are still marked, since wideWidth is one then and a wide variable is laid out like any other, and no box is placed.

wideBody :: Var v => ANormal Reference v -> ANormal Reference v Source #

The body with its wide binders marked and its boxes placed. Linear in the body: one walk, with the set of the wide variables that may still hold an unboxed constructor on the current path, forked at every branch.

letYields :: Var v => ANormal Reference v -> Bool Source #

Whether a let's binding is emitted as a section of its own, whose value arrives by a yield, rather than as an instruction (a literal, a constructor, a record, a record update, a primitive, a discard, an affine update, a box): the complement of the instruction cases of the emitter's emitLet.

wideCon :: Var v => ANormal Reference v -> Bool Source #

Whether a let's binding is a small constructor application, which stays in the variable's slots under the convention.
