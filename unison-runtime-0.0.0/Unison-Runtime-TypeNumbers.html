Unison.Runtime.TypeNumbers

Description

The process-wide numbering of types.

A data constructor closure carries a packed tag: the number of its type in the high bits, the constructor's tag in the low (TypeTags). The number stands for the type's Reference wherever that is needed: to order values of different types (compareClosure), to write a value out (reflectValue) or to show it (Decompile). The comparison runs in pure code (Ord Val, the key order of a replaced Map) and has no cache in hand, and a value built by one code cache can meet a value built by another (ucm runs an ordinary and a sandboxed runtime), so the numbering is one per process, here, and not a field of the cache.

Numbers are never reused and an entry never changes once written, which is what makes the pure read (typeReference) sound: a closure carrying number n exists only after n was published, which is after its slot was written. A number reaches another thread inside a closure or a compiled group, through whatever synchronization handed those over.

Writes happen when code is loaded, rarely, and never block a reader: the number-to-reference direction is a directory of fixed chunks that are allocated on demand and never moved, read with two loads; the reference-to-number direction is an immutable map swapped atomically.

The builtin types have fixed numbers (builtinTypeNumbering), the same in every process; the compiled code of a program carries the numbering it was compiled against, and the process that runs it seeds the registry from that (seedTypeNumbers) before loading anything.
